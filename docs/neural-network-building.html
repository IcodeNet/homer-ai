AI engineering basics

A neural network is a building that learns by turning its knobs

A neural network is a program that learns from examples instead of following rules you write. Picture it as a building: data comes in at the bottom, gets changed a little on every floor, and an answer comes out at the top. PyTorch gives you the parts to build it (torch.nn), the elevator that works out what went wrong (autograd) and the repair crew that fixes it (torch.optim).

  1. Roof: the loss check (loss function)An inspector compares the building's guess with the right answer and gives a score for how wrong it was. This score is called the loss. Big number = very wrong, zero = perfect.
  2. Top floor: the output layerGives the final answer, for example "70% sure this photo is a cat".
  3. Floors 1 and 2: layersA layer is one step of work. Each floor takes the numbers from the floor below, mixes them, and passes new numbers up. More floors = the network can learn harder patterns.
  4. Knobs: weights (also called parameters)Each layer mixes numbers using its knobs. The knobs are the only thing the building can change. Learning means finding good knob settings. Real models have millions or billions of knobs.
  5. Lobby and stairs: input and the forward passData walks in as a tensor, which is just a grid of numbers (a photo becomes one number per pixel colour). Riding up through every floor is called the forward pass.
  6. Red elevator: autograd (the backward pass)Starts at the roof with the score and rides down. On every floor it leaves a note on each knob: "turn me this way, about this much, and the score gets better." That note is a gradient.
  7. Workers with spanners: the optimizerThe optimizer is the repair crew. It reads every note and turns every knob a small amount. How big each turn is is set by the learning rate.

The drawing is a way to picture it. Real layers aren't rooms, they're maths on numbers, but the order of events is exactly right.

One round of learning has four steps, repeated thousands of times

  1. 1Forward. A training example (a photo with its correct label) goes up the stairs. The top floor makes a guess.
  2. 2Score. The roof inspector compares the guess with the right answer and writes down the loss.
  3. 3Backward. The autograd elevator rides down and leaves a gradient note on every knob.
  4. 4Fix. The optimizer crew turns each knob a little in the direction its note says. Then the next example comes in.

Each turn is tiny, so one round barely changes anything. After thousands of rounds the knobs end up in positions that give good answers. That's what training a model means.

Autograd: automatic gradients

A gradient answers one question: "If I nudge this knob a tiny bit, how much does the score change, and in which direction?"

Working that out by hand for a billion knobs is impossible. Autograd ("automatic gradient") does it for you. As numbers ride up the stairs, PyTorch quietly records every calculation. When you call .backward(), it replays that record in reverse, from the roof down, and works out every gradient.

The tiny example from before: y = x₁² + x₂² + x₃² with x = 1, 2, 3. Maths says the gradient of x² is 2x, so autograd gives 2, 4, 6. Knob 3 has the biggest effect on y, so it gets the biggest note.

requires_grad=True on a tensor means "this is a knob, please track it." Layers in torch.nn switch it on for their knobs automatically.

The same building in PyTorch

import torch
from torch import nn

# The building: floors stacked in order
model = nn.Sequential(
    nn.Linear(4, 8),   # Floor 1: a layer with knobs
    nn.ReLU(),         # stairwell filter (see word list)
    nn.Linear(8, 8),   # Floor 2
    nn.ReLU(),
    nn.Linear(8, 1),   # Top floor: the answer
)
loss_fn = nn.MSELoss()                # roof inspector
optimizer = torch.optim.SGD(          # repair crew
    model.parameters(), lr=0.01)      # lr = learning rate

# Made-up practice data: 32 examples
x = torch.randn(32, 4)   # inputs
y = torch.randn(32, 1)   # right answers

for step in range(1000):
    guess = model(x)            # 1 forward: up the stairs
    loss = loss_fn(guess, y)    # 2 score on the roof
    optimizer.zero_grad()       # wipe last round's notes
    loss.backward()             # 3 autograd elevator down
    optimizer.step()            # 4 crew turns the knobs

The data here is random, just to show the shape of the loop.

Word list

Neural network (model)
The whole building: layers stacked together that turn inputs into a guess.
Tensor
A grid of numbers, the only thing that moves through the building. One number is a tiny tensor, a photo is a big one.
Layer
One floor. nn.Linear is the most common kind: it multiplies the incoming numbers by its knobs and adds them up.
Weights / parameters
The knobs. The numbers the model changes while it learns.
Activation (ReLU)
A simple filter in the stairwell between floors. ReLU keeps positive numbers and turns negative ones into 0. Without it, stacking floors would be no better than one floor.
Forward pass
Data riding up through every floor to make a guess.
Loss / loss function
The score for how wrong the guess was, and the rule that calculates it. MSELoss means "average of the squared differences".
Gradient
A note on a knob saying which way to turn it, and how strongly, to lower the loss.
Autograd / backward pass
PyTorch's tool that works out all the gradients automatically, from the roof down. Run with loss.backward().
Optimizer
The crew that turns the knobs using the gradients. SGD ("stochastic gradient descent") is the simplest one; Adam is a popular smarter one.
Learning rate
How big each knob turn is. Too big and the knobs overshoot; too small and learning takes forever.
Training
Repeating forward, score, backward, fix, many times until the guesses are good.
